# 请求时区插件 v0.1.1

这是独立的 Linux AMD64 插件，自带配置页面。无需替换 CPA 后端二进制或修改
`config.yaml`。要求宿主已支持插件；已使用定制版 v4.0.24 进行加载测试。
要从后台免二次登录，请同时替换本次提供的 `management.html`，并刷新浏览器。
旧前端仍然可用，但会保留手动输入管理密钥的方式。

## 安装

1. 校验 `SHA256SUMS`，将 `codex-timezone.so` 上传到服务器配置的 `plugins.dir` 目录。
   不要修改文件名，不要覆盖其他插件。首次手动放入文件后，重启 CPA 服务加载。
2. 在管理端“插件”中开启插件总开关，启用 `codex-timezone`。
3. 在新版后台打开插件的“请求时区”菜单，会自动复用后台登录，无需再次输入密钥。
   单独打开插件地址、旧版后台或无法建立同源通信时，仍需输入管理密钥（不是 API Key）。
   插件中的密钥仅保留在当前页面内存，不保存到插件文件或浏览器存储，也不放到 URL 中。
   后台退出登录或插件收到 401/403 时，会清除插件登录状态。
4. 打开启用开关，默认策略选择“按出口 IP”，保存，点击“刷新出口”。
5. 账号行显示出口 IP、识别时区和更新时间后，再发测试请求。可用现有抓包功能检查
   上游请求体中的 `<timezone>` 是否改变。

初次安装默认不改写。配置保存后对后续请求生效，不需要为调整规则重启 CPA。
服务器需要允许相应出口访问 `https://ipwho.is/`；查询只发送普通 GET 请求，不携带
账号令牌、代理密码或业务请求内容。部署前请确认外部服务的使用条款和可用性。

## 设置规则

- 账号策略优先，选择“继承默认”则采用默认策略。
- “保持原样”：不改写该账号请求。
- “指定时区”：从可搜索的时区列表选择，也可输入有效 IANA 时区。
- “按出口 IP”：账号代理优先；账号没配代理时走宿主全局代理；`direct` 或 `none`
  表示该账号明确直连。未显式配置代理时沿用宿主默认传输行为。

只处理已存在的用户环境时区和搜索工具时区，不修改日期、时间、模型、思考深度、
Fast 或请求头规则。首次识别失败保持原样；后续失败保留上次结果并显示错误。
成功结果缓存 6 小时，失败自动重试间隔 5 分钟。手动刷新绕过缓存等待。
账号代理配置每分钟同步；更改代理后建议先点击刷新出口，再测试。
无请求、也没有打开插件页面时，后台定时查询会暂停，恢复使用后异步刷新。

## 文件与权限

设置默认保存在 CPA 工作目录下的 `plugins/data/codex-timezone.json`。
该目录须能被 systemd 的实际运行用户写入；不要为了修权限设置 `chmod 777`。
可在插件自身配置中调整 `data_file`。不要新增第二个顶层 `plugins:` 或 `configs:`。
插件不会修改你的主 `config.yaml` 或认证文件。关闭插件会保留规则。

## 边界

- 保持现有 `codex.response-steering: false`，即默认值。可选双向快速路径的后续帧
  会绕过宿主账号后置钩子；不改宿主的插件不能覆盖这些帧。普通 HTTP 和默认串行
  WebSocket 不受这个限制。
- 自动模式面向物理 Codex OAuth 认证文件；无法读取代理信息的账号会跳过并提示。
- 其他插件设置的单次请求代理覆盖不在该钩子的可见范围内，应对此类请求使用手动时区。
- IP 定位可能不准确。轮换 IP、分流代理可能让查询服务与 OpenAI 使用不同出口。
- 当前二进制要求 Linux x86-64、glibc 2.34 或更高，不适用于 Alpine/musl 或 ARM。

撤回时先在插件页禁用；需要删除文件时停止 CPA，只移除本插件 `.so` 后再启动。
不要删除其他插件，也不用回滚主程序。
